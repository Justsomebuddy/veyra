**Date:** 2026-08-07
**Status:** philosophical closure audit; no new theorem, certificate, or promotion
**Scope:** one exact prime-power doctrine, not a universal model of arithmetic

## 1. Four layers

Veyra must keep four kinds of statement separate even when one artifact touches
all four.

1. **Ontology** names the admitted entities and their identity conditions:
   integer source, productive process, compatible family, completed carrier,
   observers, presentations, and history-relative tokens.
2. **Semantics** names the maps and laws between those entities: evaluation,
   restriction, translation, path composition, realization, projection, and
   scoped equality.
3. **Epistemology** names why a judgment may be accepted: exact raw source,
   witness, captured theorem, assumption ledger, obstruction, or typed OPEN
   boundary. Evidence identities are never object identities.
4. **QA and governance** check implementations through attacks, focused tests,
   certificates, continuity, resource caps, review, versions, and logs. Passing
   QA does not create an ontological object or mathematical bridge.

No layer may silently discharge an obligation belonging to another layer.

### 1.1 Existence/status profile

[Doc 151 §4](151_veyra_philosophical_kernel_p2.md#4-existence-is-a-typed-profile)
defines ten orthogonal judgments that this audit must preserve:

| Status | Exact positive content |
|---|---|
| `presented` | a representation is supplied |
| `admissible` | it satisfies a named doctrine |
| `observable` | an admitted coupling returns a typed response |
| `constructible-in` | a closed constructor and its exact premises are available |
| `generable` | a bound process freshly replays it |
| `denoted-in` | an exact semantic rule assigns content to the occurrence/presentation |
| `consistent-premise-slice` | the exact formation slice is conflict-free or proved isolated |
| `coherent` | every declared compatibility obligation passes |
| `persistent` | named continuation witnesses preserve its trace |
| `stable` | declared alternative paths reconcile |
| `refinement-robust` | demanded genuine refinements preserve the formation |
| `witnessed` | replayable evidence supports the exact judgment |
| `scoped-object` | a named formation rule adopts the structured presentation in its scope |

This is not a linear ladder, and no row promotes an artifact to another row.
In particular, `witnessed` is epistemic support rather than object formation,
while `scoped-object` is ontology relative to a named rule and scope rather
than absolute existence. Presentation need not imply generability, finite
coherence need not imply a completed carrier, and a positive silent
observation need not imply absence. Any conversion requires its own named,
typed promotion rule; adjacency in this table supplies none.

Three further distinctions govern positive construction without adding casts:
`constructible-in(D,S)` is modal—a closed constructor and its premises are
available; `generable` records an actual fresh source-causal production trace;
`denotes-in(D,S)` is a semantic relation from that occurrence/presentation to
content; `scoped-object` is the later canonical adoption judgment. Separately,
`consistent-premise-slice` says the exact formation premises have no declared
conflict (or are protected by a proved isolation rule). It is neither an object
nor a witness that the surrounding doctrine is globally consistent.

## 3. The vertical chain

The intended model is not a bag of certificates but one source-compatible
chain:

```text
z -> G_z -> F_z -> Family_p -> ZpVeyra(p) -> rho
```

This is a semantic presentation chain, not proof-dependency order: PΩ2 and N1
are independently sourced, N3 consumes both, and N2 consumes no PΩ2 final
judgment. Doc 154 §10 gives the non-circular dependency DAG.

- `z` is the exact integer source under the exact prime/tower doctrine.
- `G_z` is the closed productive process of P3-A1b.
- `F_z(n)=z mod p^(n+1)` is the direct all-depth family of P3-N1.
- `Family_p` is the exact compatible-family class together with membership and
  compatibility evidence, not a finite residue table.
- `ZpVeyra(p)` is the PΩ2 completed carrier relative to its exposed ledger.
- `rho=(rho_n)_n` is the complete declared projection family; it is not an
  observer-free view from nowhere.

## 4. Exact model-closure criterion

For an exact prime-power package `M`, write `Closed_p(M)` only when all of the
following are established on the same committed doctrine and transitive
assumption closure:

1. every node in the vertical chain is constructed or admitted by its own
   named raw-source rule;
2. every adjacent arrow has a named judgment whose domain, codomain, source,
   theorem bytes, and ledger identities match both endpoints;
3. N2 establishes reduction identities, compositions, observer squares,
   strict separators, and equality of every required finite reduction path;
4. N3 freshly realizes the exact N1 family in the exact PΩ2 carrier and proves
   `rho_n(realize(F_z))=F_z(n)` for every `n`;
5. N4 applies the complete declared separating projection family to derive
   carrier equality only inside that carrier doctrine;
6. arithmetic-specific HAP and SFP judgments bind actualization, construction,
   persistence, and refinement survival for the same package, while every
   failure remains typed as REFUTED, OPEN, or resource/formal refusal.

The criterion is conjunctive and bridge-sensitive. In particular:

```text
Established(A) + Established(B) != Established(A -> B)
```

No certificate, shared name, equal digest length, finite agreement, or imported
classical theorem can replace the missing bridge judgment.
