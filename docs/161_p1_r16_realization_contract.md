# P1→R16 — Relative Observer Realization Contract

**Date:** 2026-08-11  
**Status:** bounded executable definition and level-1 certificate; no theorem or promotion  
**Schemas:** `p1-r16-context-v1`, `veyra.p1-r16.realization-witness.v1`  
**Origin:** design question reported in issue #13

## 1. Decision

There is no canonical map

```text
ObserverDoctrine → FiniteObserverDoctrine
```

from the current P1 value alone. P1 admits closed R11 programs and binds their
canonical bytes, response kinds, metadata, and doctrine fingerprint. It does
not choose a finite carrier, bind carrier states to recurrence inputs, totalize
partial observations, assign finite costs, or provide bottom and joins.

The implemented boundary is therefore relative:

```text
exact P1 doctrine + explicit RealizationContext
  → authoritative R11 replay on every state/program pair
  → tagged total observation classes + structured replay rows
  → bounded finite join completion
  → validated R16 doctrine + replay witness
```

Changing the context changes the realization. The implementation does not
enrich `ObserverDoctrine`, mutate the R11 semantics, or weaken the R16 doctrine
validator.

## 2. Context is explicit policy

`RealizationContext` binds every choice missing from P1:

1. a realization identifier;
2. an ordered finite tuple of canonical R16 state values;
3. one closed `Silence/Pulse` recurrence for each state;
4. one ordered nonnegative base cost for every admitted P1 observer;
5. the exact response-totalization policy;
6. the exact cost policy;
7. the exact closure policy;
8. a version and domain-separated context digest.

The first version admits at most eight source observers and 256 states. The
source-observer order and cost coverage must match P1 exactly. States are
deeply captured before hashing, equality, or replay; recurrence depth, integer
size, identifiers, source-cost cardinality and magnitude, aggregate closure
costs, payloads, and total evidence are bounded before expensive work or
canonical encoding.

Supplied witness evaluation states are also precharged as one aggregate before
per-row capture. The aggregate admits at most the eightfold expansion of the
context state budget (32,768 finite-value nodes and 2 MiB of encoded state
material), matching the maximum source count without allowing every replay row
an independent context-sized allocation. Canonical JSON payload validation
converts malformed, non-ASCII, and excessive nesting failures into the same
closed realization validation error rather than exposing parser recursion.

The sum of all nonnegative source costs must fit the bridge's fixed cost bound.
This explicit context-admissibility rule ensures that every enumerated subset
cost is representable before minimum-generator selection begins.

The context is an external mathematical parameter, not hidden configuration.
Its digest binds integrity only. It does not establish chronology, target
blindness, independence, or authentication.

## 3. `Ready | Blocked` is retained

Every admitted R11 program is decoded from its canonical bytes and freshly run
on every bound recurrence. Each `Ready` or `Blocked` result is serialized as
canonical structured JSON in a `RealizationEvaluationRow`. A row records:

- source observer and state position;
- exact captured state and recurrence commitment;
- the sum tag `ready` or `blocked`;
- a first-occurrence response-class ordinal;
- the complete structured response or obstruction payload;
- a payload digest.

R16 needs total hashable responses, while an R11 blocked run is not an echo.
The finite table therefore carries a tagged class reference:

```text
("p1-r16-totalized-v1", ((status, response-class), ...))
```

The class ordinal is assigned by exact payload equality, not digest equality.
The corresponding witness rows retain the full structured payload. Thus a
blocking reason is neither discarded nor replaced by one undifferentiated
sentinel while the source partition is computed, and SHA-256 collision
resistance does not define that partition.

The completed R16 doctrine is nevertheless an extensional partition quotient.
Bottom has no source component, and extensionally duplicate source partitions
use one minimum-cost generator set. Consequently its response table need not
repeat every source status or payload; the complete `Ready|Blocked` structure
is preserved in authoritative evaluation evidence, not claimed as an
injective encoding in every completed observer.

This is a **totalization**, not an embedding theorem for R11 `echo`. Two states
with the same structured blockage receive the same finite response, while R11
still returns `DomainBlocked`, never `Echo`, for their comparison.

## 4. Finite join completion

Each replayed source observer induces an ordered normalized partition of the
context carrier. The v1 closure policy explicitly derives:

- the indiscrete bottom partition;
- every common refinement generated by a subset of source partitions;
- one extensionally unique `FiniteObserver` for each resulting partition.

The construction enumerates at most `2^8 = 256` source subsets. A partition's
cost is the minimum sum of the declared source costs among subsets generating
it; aggregate costs are bounded before encoding and ties use exact source
order. Extensionally duplicate source programs map to
one finite partition rather than violating R16 uniqueness. Here that means
distinct admitted source programs inducing the same finite partition, because
P1 already forbids duplicate canonical programs. Every derived row
records the selected generator IDs, normalized partition, cost, and the first
carrier index representing each class.

Derived bottom and join observers are **R16 completion observers**. They are
not silently admitted P1 programs. `source_mapping` separately records where
every P1 observer lands in the completed finite doctrine.

The constructed doctrine is still passed through the unchanged R16
`validate_doctrine` gate. A generated invalid doctrine is an internal
fail-closed error, not evidence.

## 5. Witness and authoritative verification

`ObserverRealizationWitness` binds:

- the exact P1 doctrine fingerprint;
- the complete context digest;
- every structured evaluation row;
- every source-to-finite mapping;
- every bottom/source/join provenance row;
- the complete R16 doctrine and its digest;
- one terminal witness digest and fixed scope boundary.

`verify_observer_realization_r16` does not trust supplied evaluations merely
because their digests agree. It snapshots the external P1 doctrine and context,
decodes every source program, reruns R11 on the full Cartesian scope, rebuilds
the closure and R16 doctrine, recomputes all digests, and requires complete
witness equality.

The witness is a deterministic typed value, but this slice defines no portable
wire codec. Replay still requires the exact external P1 doctrine and context.
It is not a self-contained signed package and contains no authentication key or
signature.

The resource precharge is an acceptance bound, not a complexity or throughput
claim. Shared tuple references are charged by expanded occurrence so aliasing
cannot bypass the aggregate cap; exact cap values are accepted and the first
excess node or byte is rejected before per-row deep capture. The subsequent
per-row snapshot remains authoritative for exact type, depth, integer, text,
and byte limits.

## 6. Identity, composition, and quotient transport

The first contract deliberately defines no identity or composition law between
realization contexts. Such a law would additionally need typed state maps,
recurrence-input transformations, cost transport, closure compatibility, and a
proved witness-transport rule. None is inferred from matching digests.

Each closure row records the first state position in every response class. This
is a deterministic **local ordered section** relative to one context order. It
is not a canonical quotient section, natural transformation, or transport
choice across contexts.

## 7. Ready-only collapse question

The reported paper argument says that the current closed
`Input/Tail/Crest/Pair` grammar on an all-`Ready` unary recurrence scope may
produce only the chain

```text
bottom ≤ minimum-recurrence-length cut ≤ input equality.
```

The executable tests include one finite ready-only chain example and a
separate structured-blockage example. They do not prove the structural
induction claim, show that every image is a chain, establish an empty
obstruction basis, or show that the diamond family `O_n` lies outside every
future P1 grammar.

The implementation does not enrich the grammar merely to avoid the proposed
collapse. That claim should be proved or refuted separately. The explicit
totalization and closure policies make the subject of such a theorem precise.

## 8. Exact answers to issue #13

1. **Canonical realization:** no; realization is relative to an explicit
   fingerprint-bound context.
2. **Blocked:** retained in full structured replay evidence and used exactly to
   derive source partitions; the extensional completed R16 table need not copy
   every source tag or payload.
3. **Policy location:** separate `RealizationContext`; P1 and R16 remain
   independent core calculi.
4. **Evidence:** digests bind integrity, while the authoritative checker must
   replay every R11 evaluation and reconstruct the complete doctrine.
5. **Identity/composition:** not claimed until context morphisms and transport
   laws are separately typed and established.
6. **Quotient section:** only an explicit context-order-local section is
   recorded; no canonical or natural section is claimed.

## 9. Nonclaims

This release does not establish:

- a canonical P1→R16 map, semantic embedding, functor, naturality, identity, or
  composition law;
- reflection or preservation of R11 `echo` through blocked totalization;
- a P1-admitted meaning for derived bottom/join observers;
- canonical quotient transport outside one ordered finite context;
- an all-scopes ready-only image theorem or obstruction-basis result;
- an infinite/topological/probabilistic completion;
- authentication, nonrepudiation, chronology, or target independence;
- runtime optimality, mathematical novelty, Lean proof, R8 promotion, or a new
  ontology layer.
